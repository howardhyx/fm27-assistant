# 字段与关联规则

## 证据等级

- **版本诊断与结构核验**：版本和指纹不再作为准入条件。匹配历史验证组合时，`profile_validated/native_profile_validated=true` 表示存在相应验证证据；未匹配时为 `false`，只报告本次实际通过的结构及数值检查。`version_check_enforced=false` 表示版本不匹配不会阻断读取，不能将 `ok=true` 当作所有字段语义都已确认。
- **原生定义/数值交叉核对**：阵型、角色、指令来自同版枚举与读取逻辑；团队选项映射曾独立核对103项。39项统计与赛季字段、球队合计及事件计数交叉核对。部分统计名称继承社区解析定义。
- **结构已读出、含义部分确认**：额外快照、事件未命名类型、射门标记、坐标原值。明确原码，不根据看起来合理的数字赋予标签。
- **未读取/不支持**：缺失的热图、连续追踪、全触球/传球流等。不得补零、生成虚构事件，或用总数合成真实地图。

`null` 是未知/无匹配数据；`0` 是字段实际读到的零；空列表只表示当前已读结构里没有条目。检查 `coverage.truncated` 才能讨论列表完整性。

## 编号、球队和时间

| 字段 | 含义/关联方式 |
|---|---|
| 球员 `uid` | 社区解析器球员记录ID，逐场/赛季表用此关联 |
| 球员 `unique_id` | 游戏另一唯一编号，战术快照用它，不能与uid互换 |
| 比赛统计 `reference` | 当前版为pindex+1，工具已转为球员身份；引用可能找不到当前实体 |
| `team_id` | 球队ID，一线队与梯队不同；不等于club UID |
| `club_uid` | 俱乐部ID，可能对应多支球队 |
| `cache_key` | 详细缓存记录键；不是赛程match_record_id |
| `match_record_id` | 可复用的记录槽号，禁止单独用来关联历史比赛 |

比赛用游戏内日期及主客球队ID唯一关联；日期应来自该记录本身，不从缓存key大小猜。涉及历史球员所属队不能只看他现在所属俱乐部。存档修改时间是文件时间，游戏内日期是赛季世界时间，不能混为现实日期。

工具每次读取前后检查文件mtime与大小；保存中发生变化时失败重试。不同来源或文件版本不能混成一个未经说明的快照。

## 战术读取含义

- 有球/无球各有11个槽位，不能用单一“4-2-3-1”取代全部结构。先解释 `position_labels`，保留 `position_mask` 中额外列标记；未核验的左右列不要仅按槽位顺序推断。
- `current_role_name` 才是当前保存角色的内部枚举名；`stored_role_overrides`（低层结构）不是当前选择。高位 `duty_bits` 保留原码，未建立统一名称映射时不能按旧版FM职责体系擅译。
- `current_tactic_selected=null`：存档此读取方式没有确认哪套被选中。多套战术全部读取；不同球队同名副本不可混为一套。
- 个人指令读出当前角色的已存覆盖，不展开角色内建默认；空覆盖不能解释为没有限制或没有进攻职责。针对特定球员的覆盖引用如尚未命名，保留原始编号。
- `explicit_bit=false` 是该组没有额外选项位，采用该组默认选项，不是取消心态影响。标准选项也不代表不同心态下的行为数值完全相同。
- 指令组中文标签用于释义，以内部选项名与原码为准。已修正资料中反击/保持阵型的反向标签：`AttackTransitionHoldShape`=保持阵型，`AttackTransitionCounter`=反击。
- 存档快照可能落后于未保存的临场修改。球队指令并不包含已确认的全部对手针对性指令。定位球名称也不是完整套路。

### 历史比赛指令

下述原生调用链地址属于旧版 `27.0.0+2493426`。新版 `27.0.1+2494687` 已重新验证球队根、主次 creator 结构及主客交换样本，但其原生所有者链地址尚未独立推导；新版结果的 `native_reader_rvas` 留空，并提供实际 creator 首部和结构性证据，不能把旧地址当成新版原生证据。新版单场球员标量读取使用另一套已核验的原生片段，见维护说明。

`match --part tactics` 从指定比赛的缓存字节读取模拟状态中的球队主战术对象，独立于当前保存战术。按双方球队ID定位版本3球队引用及后续标量体、核对重复俱乐部ID，要求每队唯一且顺序与比赛主客一致；在各自边界内读取首个有效主对象，并校验后继次对象。原生调用链为 `4973930 → 15bde0 → MATCH_MANAGER::read(16c160) → 16dc80 → 16fca0`；主对象写入经理 `+0x1818`，次对象不作为主战术。对象的11个双阶段槽位、排列、角色枚举和指令互斥关系继续检查。

这是有界结构定位与部分对象解析，尚未逐字段走完整个比赛状态。当前验证包含主客交换、三场不同命名战术和历史设置差异；不能推广成所有缓存布局均可读。主对象前的80字节不透明预设尾部也须符合已验证布局，防止主对象签名损坏后悄悄跳到默认模板；该字节模式尚无完整字段释义，新变体保持不支持。定位缺失、歧义或越界直接失败，不按名称挑一个看似合理的对象，不把周围的默认 `4-4-2` 模板当作比赛战术。`evidence` 保留定位依据和原始偏移。

单独的 `tactics` 只返回静态主对象。配合 `tactic-timeline`，可以把它放在记录的修改队列之前作为序列化基线；不能当作最后或全场不变设置。是否存在零时刻修改也须检查。`opening_tactic_confirmed=false` 不等于缺少基线，而是没有模拟并核验全部开场有效行为。未知非零球队位、职责位和特定球员覆盖原码仍须保留；已命名个人指令只表示当前角色的存储覆盖，不等于全部有效行为。

### 带时间的修改记录

`tactic_timeline.py` 对应原生 `49740d0` 队列读取器、`49744b0` 七字节公共头和 `4aa6010` 类型工厂。公共头顺序为类型u8、原生时刻u32、所属一方u8、记录分钟u8；载荷由类型的读取方法决定。当前适配队列revision68，限1000条；仅在帧末64KiB且主对象之后寻找候选，要求唯一、计数全部满足并精确消费至帧末。没有逐字段走通前方全部模拟状态，不把结构定位说成全存档解析。

已验证三场共55条记录、11次换人，其换上/换下时刻与独立比赛球员统计完全相等。支持类型1/25（有球/无球单槽完整设置）、4（换人）、7（讲话结构）、8（战术改名）、9（人工控制标记）、13（基础球队设置替换）、14（标记）、17（场边讲话结构）、24（有球到无球槽位映射）、27/28（快捷调整启用/移除）。部分类型的完整语义仍保留原码，其他类型明确不支持；不能跳过未知载荷后接着读。

`recorded_minute` 是读取的分钟字段，`native_tick` 用来确定先后顺序和关联统计；保留原值，不统一除60/100/240，也不自行写成精确秒或45+/90+格式。同一时刻的多条命令保持原始顺序。

类型13的 `base_setting_changes` 比较相邻基础设置对象，包括心态；它**没有叠加快捷调整**。例如基础心态保持进攻时，随后启用的快捷调整仍可能覆盖为全力进攻。类型27返回当前枚举中的 `tweak_name` 和载荷内实际绝对覆盖/档位变化/心态覆盖，类型28移除对应项。快捷调整与基础设置、角色默认、心态上下文和相互冲突的最终合并尚未完整模拟；不能仅凭一列基础设置生成所谓完整有效战术。

队列是“记录下来的修改过程”，不保证包含对手AI的每项自动决策、未记录的动态行为或每个游戏版本的所有更改类型。没有战术改名事件不等于没有临场调整；名称不变时仍可能有指令、角色、位置和快捷调整变化。

## 比赛统计与事件

- 原始位置熟练度、体能、锋利度、时刻等单位分别理解，不统一除100。球员上下场tick不能直接当分钟；事件已有名义分钟与补时字段时使用它们。
- `shots` 与 `advanced-shots` 是不同结构，不能假定一一对应。附加射门可能是状态变化记录，尚未完整命名。坐标看起来像球门平面，也不能称为已确认的起脚位置。
- 球员逐次射门中的码1与进球相符，码1+4与射正相符；其余码保留未确认标签。不要只凭总数给码2/3命名。
- 事件表的进球、乌龙、点球进球、红黄牌有明确类型映射。事件分钟可能是向上显示的名义分钟，精确射门秒与进球事件可能有一个tick或一秒的差别，原值均保留。
- 不把 `unconfirmed` 事件命名成取消进球、伤病、越位或换人。关联球员在同队、有效索引且不是进球者时才可用于核对助攻；乌龙不自动生成助攻。
- 39项通用统计中的 `blocks` 与 `shots_blocked` 保留各自字段名，不能随意互换。门将某些字段口径可能与外场不同，应使用专用字段/赛季表，不将外场争顶等直接替代扑救。
- xG/xA先逐场四舍五入至0.01再累计时，可能与未舍入逐场值总和略有差异。赛季距离按逐场向下截断至0.1km后累计，和未截断比赛值总和不同。
- 相同赛季字段也可能包含其他球队时期；累计范围不匹配时先查球队、赛事和时间，不能强制让总数一致。

## 球员、合同和财务

公开属性仍来自整个存档数据库，不等于当前经理视角下已侦察到的信息。不要把CA/PA、隐藏比赛属性、性格作为公开属性混入；本工具不提供这些导出。

身价不是可成交转会费；工资原值没有独立核实其界面单位时不要自动称周薪。租借球员的当前队、母队、合同队需分别读取。`contract.end_source` 区分合同与球员记录回退，未确认期限不能假设到某年夏天。

财务是历史月末与存档基础币种。`wage_budget_weekly/wage_payroll_weekly` 有明确weekly名称；月末转会预算不能直接宣称为存档当天可花额度。无确定汇率或显示币种时只标“存档原值”。
